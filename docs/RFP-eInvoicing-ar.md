## طلب عرض فني ومالي (RFP) لمنصة الفاتورة الإلكترونية وربط الجهات وبناء السجل الضريبي الموحد

### 1) المقدمة
تسعى الجهة الطالبة إلى تنفيذ منصة وطنية متكاملة للفاتورة الإلكترونية (e-Invoicing) وفق نموذج CTC (Clearance/Reporting/Hybrid)، وربط مصلحة الضرائب بالجهات ذات الصلة (البنوك، الجمارك، منصات المدفوعات، والضمان الاجتماعي)، وبناء سجل ضريبي موحد للمكلفين (TIN Registry). تهدف المنظومة إلى رفع الامتثال، تقليص فجوة التحصيل، وتحسين جودة البيانات واتخاذ القرار.

### 2) نطاق العمل
- تصميم وتنفيذ وتشغيل منصة e-Invoicing متوافقة مع أفضل الممارسات العالمية (UBL/CTC).
- بناء وإدارة سجل ضريبي موحد (TIN) وربطه آلياً مع مصادر البيانات.
- تكاملات مؤسسية آمنة مع البنوك والجمارك ومنصات المدفوعات والضمان الاجتماعي.
- بنية أمنية متكاملة (IAM, PKI, HSM/KMS, WAF, SIEM) وإدارة هويات وصلاحيات.
- تحليلات ومخزن بيانات ولوحات مؤشرات KPIs واكتشاف احتيال تدريجي.
- حوكمة بيانات، سياسات احتفاظ، والامتثال للتشريعات المحلية والدولية.
- التسليم المرحلي بدءاً بكبار المكلفين وصولاً للتغطية الكاملة خلال 18–36 شهراً.

### 3) المتطلبات الوظيفية الرئيسية
1. إدارة الفاتورة الإلكترونية:
   - نماذج فواتير B2B/B2C بدعم ضرائب متعددة (VAT، دخل إن لزم).
   - توقيع إلكتروني JWS/JAdES، أختام شركات، طوابع زمنية، رموز QR.
   - تدقيق فوري/قائم على القواعد مع نمط Clearance أو Reporting وفق السياسة.
   - إدارة المرفقات، حالات الفاتورة، الإشعارات، والإلغاء/الاستبدال Credit/Debit Notes.
2. السجل الضريبي الموحد (TIN Registry):
   - تسجيل وتحديث بيانات المكلف والمنشآت والملكية والالتزامات.
   - ربط موافقات ربط الحسابات البنكية ومراجع الموافقات وانتهائها.
   - درجات مخاطر محدثة دورياً.
3. التكاملات المؤسسية:
   - بنوك: كشوف/حركات مجمّعة آمنة (API/SFTP)، نمذجة الحركات، المطابقة مع الفواتير.
   - جمارك: ربط إقرارات الاستيراد/التصدير ومطابقة قيم CIF/FOB.
   - مدفوعات: بطاقات/محافظ/فواتير فورية، مرجع تسوية موحد.
   - ضمان اجتماعي: مطابقة الرواتب والمساهمات لاكتشاف عدم الاتساق.
4. التقارير والتحليلات:
   - KPIs تشغيلية ورقابية، تقارير التزام، تحليلات فجوة ضريبية.
   - خارطة طريق لاكتشاف الاحتيال (قواعد → ML → Graph).

### 4) المتطلبات اللاوظيفية
- الأداء: P95 < 300ms للعمليات الحرجة، ≥ 500 TPS قابلة للتوسع.
- التوافر: 99.95%، دعم تعدد المناطق، RPO ≤ 15 دقيقة، RTO ≤ 1 ساعة.
- الأمان: Zero Trust، mTLS، تشفير بالراحة والنقل، IAM (OIDC/OAuth2, RBAC/ABAC, MFA)، DLP، SIEM/SOC.
- القابلية للتوسع: بنية خدمات مصغرة على Kubernetes، CI/CD، IaC.
- القابلية للصيانة: ملاحظة تشغيلية (APM، Logs، Metrics، Tracing) ولوثائق كاملة.

### 5) البنية المرجعية التقنية
- قنوات: بوابة ويب، تطبيقات جوّال، تكامل B2B عبر API.
- بوابة API: إدارة مفاتيح، حدود معدّل، سياسات، مراقبة.
- خدمات: Invoice Service، Taxpayer Registry، CTC Clearance، PKI & Signing، Integration Hub، Risk & Analytics، Notifications، Reporting & Audit.
- البيانات: OLTP (PostgreSQL/MySQL)، وثائق (MongoDB) للفاتورة JSON، Cache (Redis)، بحث (Elasticsearch)، تدفق (Kafka)، مستودع بيانات/بحيرة.
- الأمن والحوكمة: IAM، mTLS، HSM/KMS، WAF، SIEM، DLP، Data Lineage.

### 6) PKI والتوقيع الإلكتروني
- إصدار شهادات عبر CA/RA، إدارة دورة الحياة (CSR، OCSP/CRL، الإبطال).
- توقيع بعيد عبر HSM/Cloud HSM، دعم eSeal للشركات.
- سياسات توقيع، طوابع زمنية، سجلات WORM، وملفات تدقيق غير قابلة للعبث.

### 7) حوكمة البيانات والامتثال
- تصنيف البيانات، سياسات الاحتفاظ (فواتير/تدقيق 10 سنوات)، إخفاء/تقليل بيانات.
- اتفاقيات مشاركة بيانات DSA/DUA مع الجهات، أسس قانونية، آليات سحب الموافقة.
- الامتثال: حماية البيانات، التوقيع الإلكتروني، الأرشفة القانونية.

### 8) متطلبات الاختبار والاعتماد
- بيئة Sandbox، أدوات تحقق ذاتي، حِزم SDK (Java/.NET/Python/Node/PHP).
- اختبارات وحدات/تكامل/تحمل/أمن/تعافي، بيانات اختبار معيارية.
- معايير قبول للـ Pilot ثم للتعميم الوطني.

### 9) خطة التنفيذ والمرحلة الزمنية
- 0–3 أشهر: التخطيط، RFP، تشكيل الفرق، PKI أولي، Sandbox.
- 4–6 أشهر: الأساسيات (API Gateway، Registry، PKI، Invoice Service)، بدء التكاملات.
- 7–12 شهراً: Pilot كبار المكلفين، CTC Clearance، تطبيق صغار التجار.
- 13–24 شهراً: توسع للقطاع المتوسط، تحليلات متقدمة، حملات تبنّي.
- 25–36 شهراً: تغطية كاملة، تحسين الأداء، أتمتة رقابية.

### 10) إدارة المشروع والحوكمة
- لجنة توجيهية مشتركة، إدارة تغييرات وإصدارات API.
- تقارير تقدم شهرية/ربع سنوية، مؤشرات أداء محددة، خطة اتصال.

### 11) المتطلبات التشغيلية (SLA/OLA)
- دعم 24/7، زمن استجابة الحوادث حسب الأولوية، أوقات إصلاح محددة.
- مراقبة استباقية، SRE، Runbooks للتعافي من الكوارث.

### 12) مخرجات قابلة للتسليم
- وثائق التصميم التفصيلي، OpenAPI/SDKs، مخططات ERD/JSON Schemas، سياسات أمن/بيانات، Runbooks DR، خطة إطلاق، لوحات KPIs.

### 13) أهلية المورد ومتطلبات التقديم
- خبرة مثبتة في منصات e-Invoicing/CTC وPKI والتكاملات الحكومية.
- شهادات أمان وجودة ذات صلة (ISO 27001/22301) وفِرق محلية/إقليمية.
- مقترح فني تفصيلي مع خطة تنفيذ، مخاطر وتخفيف، وPoC اختياري.

### 14) معايير التقييم ومصفوفة الترجيح
- المطابقة الفنية (30%)، الأمان والامتثال (20%)، الأداء/قابلية التوسع (20%)، خبرة المجال (15%)، التكلفة (10%)، الانتقال والدعم (5%).

### 15) هيكل التسعير وبنود الدفع
- تراخيص/خدمات سحابية، تكاليف HSM/KMS، SIEM، تكاملات، تطوير وتشغيل.
- دفعات على مراحل مرتبطة بقبول مرحلي ومؤشرات قابلة للقياس.

### 16) متطلبات PoC (اختياري/إلزامي حسب الجهة)
- بوابة API + Invoice Service + PKI Adapter + Clearance Stub + Registry Stub.
- إرسال/قبول 1,000 فاتورة/ساعة، توقيع JWS، QR، تقارير أساسية.
- نشر على Kubernetes/Containers، مراقبة أساسية، وثائق ونماذج بيانات.

### 17) ملحقات
- نماذج الفاتورة JSON وSchema، مقتطف OpenAPI، خرائط حقول للتكاملات.
- جداول السجل الضريبي المقترحة، سياسات بيانات، قوالب تقارير KPI.
